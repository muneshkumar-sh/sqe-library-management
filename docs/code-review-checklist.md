\# Code Review Checklist — LibraryHub



Use this checklist when reviewing a GitHub Pull Request.



\## 1. Correctness



\- \[ ] Does the code implement the requested functionality?

\- \[ ] Are calculations and conditional statements correct?

\- \[ ] Are boundary conditions and edge cases handled?



\## 2. Tests



\- \[ ] Are relevant unit tests included?

\- \[ ] Do tests cover normal inputs and edge cases?

\- \[ ] Do tests verify behavior rather than implementation details?



\## 3. Readability



\- \[ ] Are function and variable names meaningful?

\- \[ ] Is the code easy to follow and consistently formatted?

\- \[ ] Are docstrings or comments provided where necessary?



\## 4. Design



\- \[ ] Does the implementation fit the existing LibraryHub architecture?

\- \[ ] Is unnecessary duplication avoided?

\- \[ ] Are functions focused on a clear responsibility?



\## 5. Risk



\- \[ ] Could the change break existing functionality?

\- \[ ] Are invalid inputs handled safely?

\- \[ ] Are there avoidable performance or security concerns?
